# ivLyrics 통합 검증 기록

2026-10-09, Windows x86_64 로컬 수정판. 기준 Spotifast 커밋:
`12deee472ee87e2c9ed0e0f13730cbdd9a6cfa45`.

## 통과

- Rust 1.98.0 Windows GNU: `cargo test --locked --no-default-features --features demo --all-targets`.
  라이브러리 976개, CLI 13개, 명령 통합 3개, 로케일 1개, 예제 2개로 총 995개 통과.
- 임시 자격 증명 저장/조회/삭제 및 알송 실제 공개 서버 조회 별도 검증.
- `cargo clippy --locked --no-default-features --features demo --all-targets -- -D warnings`.
- `cargo fmt --all --check`, `git diff --check`, 번역 카탈로그 갱신 검사.
- MilkDrop을 제외한 doctest 및 경고를 오류로 처리한 rustdoc 생성.
- 데모 화면 캡처: 밝은/어두운 전체화면, 좁은 전체화면, 설정, 알송 후보, 가사 패널.
- `cargo build --release --locked --no-default-features --bin spotifast`.
  배포 실행 파일에는 데모 기능과 MilkDrop이 포함되지 않는다.

  모든 글자, 일본어·영어 예시의 지원을 확인했다.
- Windows 트레이 및 작업 표시줄의 재생 버튼을 번역했다. 언어 변경 시 표시를
  갱신하며, 한국어 버튼 문구를 회귀 테스트로 확인했다.
- 자동 테스트 992개와 clippy, 번역 카탈로그 검사, msgfmt 검사를 다시 통과했다.

- 한국어 설정, 밝은/어두운 가사 화면과 760px 폭 화면, 일본어/영어 가사 화면을

  좌우 반전, 1열/2열, 재생 조작 위치·표시 옵션을 실제 렌더링에 연결했다.
- 한국어·일본어·영어 설정 화면에서 접근성 입력으로 카테고리 이동, 슬라이더 편집,
  적용 전 값 유지와 적용 후 저장을 검증했다. 이전 설정 호환과 범위 밖 값 보정도
  회귀 테스트에 포함했다.
- 자동 테스트 994개 통과, 실환경 검사 3개는 이번 UI 변경에서 반복하지 않았다.
  `clippy -D warnings`, 포맷·번역·공백 검사도 통과했다.
- 밝은/어두운 1280×800 전체화면·설정, 760×800 좁은 화면, 1100×800 메인 화면,
  좌우 반전과 1열 배치를 확인했다. 변경 전후 HTML 비교와 PNG를 로컬 출력 폴더에 보관했다.
- 기본 UI 팔레트의 배경·텍스트·강조색을 무채색으로 변경했다. 앨범 이미지,
  사용자 지정 테마, 오류·경고의 의미 색상은 원래 용도를 유지한다.

## 재생 조작·글꼴·창 모양 추가 검증

- 재생/이전/다음 버튼과 진행·음량 막대 간격을 확대하고, 전체화면 아이콘으로
  진입 버튼을 변경했다. 상단 AI 버튼은 제거했다.
- 상단 도구의 숨김과 Tab 접근, 현재 제공자 표시 및 알송 후보 버튼의 조건부
  표시를 접근성 트리로 검증했다. 가사 가장자리의 대칭적인 투명도와 중앙 유지,
  실제 가사와 미리보기의 동일한 글자 크기·굵기도 회귀 검사에 포함했다.
- 두 줄 기본값 `32/34`, 세 줄 `32/20/34`, 배경 어두움 `0.050`과 설정 저장 왕복을
  검사했다. 기존 설정의 새 창 모양 이행 및 이후 사용자 선택 유지도 검사했다.
- Winamp 스킨 UI와 단축키 진입이 다시 나타나지 않는지 확인했다. 내부의
  공유 구현과 기존 스킨 파일은 보존하며, 스킨 UI는 제공하지 않는다.
- 자동 테스트 996개(라이브러리 977, CLI 13, 명령 3, 번역 1, 예제 2) 통과.
  실환경 검사 3개는 반복하지 않았다. clippy·포맷·번역·공백 검사도 통과했다.
- 한국어 전체화면, 상단 도구 표시, 760px 좁은 화면, 메인 가사 패널과 설정을
  데모 캡처로 확인했다. 배포 파일은 MilkDrop과 데모를 제외한 최적화 빌드다.

## 한 페이지 설정·미니 플레이어·자간 추가 검증

- 설정을 720px 최대 폭의 단일 스크롤 페이지로 바꾸고, 정렬 선택 버튼을 메인
  설정과 같은 알약 모양으로 통일했다. 설정 초안·적용·저장 검사는 유지했다.
- 가사 자간(-2~12px), 기본 ON인 사이드 가사 자동 맞춤을 추가했다. 한글·일본어·영어
  레이아웃에서 자간이 실제 폭에 반영되는지, 자동 맞춤 시 명시적인 행 수와
  32/20/34 비율이 유지되는지, OFF에서 줄바꿈이 복원되는지 검사했다.
- 미니 플레이어의 진입·복귀에서 창 크기·전체화면 상태를 복원하고 재생 상태가
  유지되는지 검사했다. 380×600 데모 화면도 확인했다.
- 스펙트럼·파형 표시 코드와 설정을 제거하고, 기존 저장값이 있어도 효과나
  빈 영역 클릭 동작이 다시 나타나지 않는지 검사했다. 오디오 이퀄라이저는 유지한다.
- 배경은 앨범 대표색 그라디언트로 변경했다. 데모/오프라인에서도 허용된 앨범색
  응답을 반영하도록 수정하고 회귀 검사를 추가했다.
- Windows의 undecorated shadow가 WM_NCCALCSIZE에서 만드는 1px 상단 오프셋을
  확인하고 해당 그림자를 창 생성 시 껐다. 원형 버튼은 크기만 확대하며
  최소화·최대화/복원·닫기 순서를 유지한다. 내부 기호 없이 색상으로 피드백한다.
- 아이콘 SVG·Windows ICO·macOS PNG를 회색/흰색 파형으로 맞췄다. 여러 크기의
  투명 모서리·무채색 픽셀·트레이 템플릿과 일곱 ICO 크기를 검사했다.
- 자동 테스트 997개(라이브러리 978, CLI 13, 명령 3, 번역 1, 예제 2) 통과.
  실환경 검사 3개는 반복하지 않았다. clippy와 포맷·번역·공백 검사도 통과했다.
- 직접 창 조작은 사용자의 Esc 입력으로 중단했다. 이후 추가 창 입력을 하지 않았다.
  실제 다른 창으로 포커스를 옮기는 재현 검사는 끝내지 못했다. 캡처와 자동 검사는
  별도 데모 데이터에서 수행했으며 사용자의 재생 중인 앱은 수정하지 않았다.

## 앨범 배경 복원·공통 축소·플로팅 가사 검증

- 흐린 앨범아트 배경과 설정창의 대표색 그라디언트를 별도 설정으로 분리했다.
  이전 `background_art` 값은 설정창 그라디언트로 읽고, 복원한 앨범 배경은
  기본 ON으로 시작한다. 이 저장 형식 호환을 검사했다. 메인 앱의 기존 앨범색은 유지한다.
- 사이드 가사의 축소 비율을 곡 전체에서 한 번 계산해 모든 시각에 공통 적용한다.
  긴 3행 묶음과 짧은 3행 묶음의 실제 글자 크기가 일치하는지 검사했다.
- 미니 플레이어의 앨범 버튼을 접근성 입력으로 눌러 플로팅 가사와 앨범 화면을
  왕복했다. 창 크기는 유지하며, 작은 앨범·곡 정보, 중앙 가사, 아래의 재생·음량·
  기능 버튼을 한 열로 배치한다. 다른 창 위 표시와 해제 명령도 검사했다.
- 미니 창 버튼은 상단 호버 또는 Tab 접근 때만 나타난다. 380×600의 일반·호버·
  플로팅 상태, 760×800 플로팅, 전체화면·설정·사이드 가사를 데모로 확인했다.
- Windows 창 그림자를 일반 창에서 복원하고, 전체화면 진입 중이나 전체화면인
  동안에는 끄는 조건을 검사했다. 프레임 전후에 실제 창 상태와 동기화한다.
- 자동 테스트 1,000개(라이브러리 980, CLI 14, 명령 3, 번역 1, 예제 2) 통과.
  clippy·포맷·번역·공백 검사도 통과했다. 실환경 검사 3개는 반복하지 않았다.

## 제공자·알송 2열 화면·미니 오버레이 검증

- 제공자 카드 순서의 중복·누락·기존 설정 이행·저장 왕복, 특정 제공자 고정을 검사했다.
  Spotify/LRCLIB 캐시를 사용해 실제 조회 순서와 강제 선택 시 다른 제공자로 넘어가지
  않는 동작을 네트워크 없이 확인했다. 팝업의 Spotify 선택과 카드 이동·적용은
  접근성 입력으로 검사했다. 메인 설정의 검색 결과에서도 ivLyrics 설정이 열린다.
- 가사 묶음 간격은 0~120px 범위로 검증하고, 새 기본 글자 크기와 굵기 및
  사이드 패널의 38/20/40 비율을 확인했다. 기존 사용자 설정은 덮어쓰지 않는다.
- 미니 조작부의 중간 애니메이션 좌표, 접힘·펼침 모두에서 재생 시간바가 보이는지,
  이전 가사 한 묶음이 현재 가사 위에 보이고 조작부 전환으로 좌표가 변하지 않는지 검사했다.
  조작부는 같은 앨범 배경을 불투명하게 다시 그려 뒤의 가사를 가린다.
- 전체화면 오른쪽 호버 재생목록과 미니 플레이어의 하단 재생목록은 동일한 대기열
  구현을 사용한다. 화면 모드·가사 기준 위치를 유지하고 메인 페이지로 나가지 않는지
  검사했다. 닫기·Esc·Q와 기존 재생·대기열 동작을 재사용한다.
  두 대기열 모두 앨범 배경을 같은 좌표에 다시 그려 뒤의 가사를 가리고,
  밝은 텍스트를 사용한다. 일반 화면의 대기열 팔레트와 행 동작은 유지한다.
- PiP 고정·해제는 실제 뷰포트 명령이 AlwaysOnTop/Normal로 바뀌고 창 크기가
  바뀌지 않는지 검사했다. 다른 앱 위에 놓는 물리적인 창 조작은 별도로 하지 않았다.
- MilkDrop의 실행 코드·설정·버튼·단축키·projectM 의존성을 삭제했다.
  해당 기능 전용 테스트도 함께 제거했으며 나머지 검사는 유지했다.
- `cargo test --locked --all-features --all-targets`: 995개 통과
  (라이브러리 975, CLI 14, 명령 3, 번역 1, 예제 2). 실환경 검사 3개는 제외했다.
  `clippy -D warnings`, 전체 기능 doctest와 경고를 오류로 처리한 rustdoc도 통과했다.
- 기본 구성의 `cargo test --locked --all-targets`도 968개 통과했고,
  기본 구성·전체 기능 구성의 clippy, 서식·번역 카탈로그·공백 검사를 통과했다.
  데모 전용 테스트는 `demo` 기능에서 실행하며 기본 빌드에 데모 코드를 넣지 않는다.
- 380×600 미니 창의 접힘·펼침·재생목록, 1280×800 전체화면 재생목록,
  밝은/어두운 설정과 알송 후보, 760×800 알송 후보를 실제 데모 캡처로 확인했다.
  캡처의 곡·가사는 샘플이며 실제 Spotify 재생이나 AI 응답을 뜻하지 않는다.
- 최적화 기본 빌드와 배포 실행 파일의 `--version` 실행을 확인했다.
  DLL 가져오기는 Windows 시스템 DLL뿐이며 별도 MinGW/MSVC 런타임은 요구하지 않는다.

## 추가 다듬기 검증 (Polished, 2026-10-10)

- 오른쪽 패널의 **가사 · 재생 대기열 · 최근 기록**을 한 줄의 탭으로 통합했다.
  중복 대기열 탭을 없애고 저장 버튼은 ‘지금 재생 중’ 제목 옆으로 옮겼다.
  탭 전환·최근 기록 선택·중복 여부를 검사했고 패널의 전체화면 버튼을 제거했다.
- 충분히 큰 가로형 플로팅 창에서는 앨범과 가사의 2열 배치를 사용한다.
  작은 창·세로 창으로 돌아오는 조건, 앨범 클릭 전환, 곡 제목과 재생 조작 위치를 검사했다.
- 싱크 드래그는 25ms 단위로 움직인다. 중간의 한 줄 알송 가사는 가까운 두/세 줄
  묶음의 첫째 줄 크기와 굵기를 따른다. 가사 경계는 배경 블록 없이 글자 투명도로 처리했다.
